# Bebop playground

This app exercises `@bebopdev/core` and mounts the first-party `@bebopdev/admin` package. Bebop owns the Better Auth adapter, JWT plugin, Admin plugin, and Users list; the playground supplies the Vite host, Jazz provider, handler mount, secret, and public URL. Access to `/admin` is checked server-side with Better Auth's Admin plugin before the UI is mounted.

Add `BETTER_AUTH_URL=http://127.0.0.1:5173` and a private `BETTER_AUTH_SECRET` to `.env` (see `.env.example`; generate the secret with `openssl rand -base64 32`). Run `pnpm generate` from the workspace root to generate Better Auth's Jazz schema, Bebop's generated schema and client, admin manifest, and permission files. Better Auth's Admin plugin controls access to `/admin` and its user APIs; `BETTER_AUTH_ADMIN_USER_IDS` can grant admin rights to additional trusted user IDs.

Jazz tooling expects a root `schema.ts`, so Bebop keeps that file as a small re-export entry point for `bebop-generated-schema.ts`.

Start the workspace with `pnpm dev`, then open `http://127.0.0.1:5173/` for the simple tasks playground or `http://127.0.0.1:5173/admin` for Bebop's admin UI. The `bebop` CLI watches `bebop.config.ts` and its local imports and regenerates the schema, permissions, and admin manifest on changes. The Jazz Vite plugin starts the local Jazz development server and watches those generated files. On `/admin`, `@bebopdev/admin` checks whether the Better Auth users collection is empty and offers its first-admin setup flow; the host provides the status route and signup handler. The server grants the admin role only while that collection has no users, and the setup prompt is skipped when a seed or earlier registration already populated it. Later signups receive the ordinary user role. The playground's root sign-in page remains its own app flow.

Create one or more workspaces from the workspace controls, then add tasks. Workspace creation atomically creates an active admin membership for the signed-in creator. The selected workspace scopes the task list and parent-task choices, and new Playground tasks inherit it without a Workspace field in the task form. Ordinary users can rename a workspace they administer. Invites and workspace deletion are not part of this example flow.

The admin can edit Workspaces, Workspace Memberships, Tasks, and Media. The Task editor in `/admin` retains its Workspace field and existing create/edit routes; it is independent of the Playground's selected workspace. Workspace Memberships use the Better Auth command route and Jazz global write confirmation; standalone membership commands are reserved for global admins. The `users` collection has `auth: true`; task and membership relationships use `relationTo: "users"` and map to Better Auth's protected Jazz user table. Each task's required `author` defaults to the signed-in user. The `/api/bebop/users` directory endpoint is admin-only; Better Auth tables remain unreadable to browser Jazz clients. Jazz separately records the actual creator in `$createdBy`.

The Users collection page is visible to Better Auth administrators and reads through the built-in Admin plugin. It provides a searchable, paginated user list and uses the Admin plugin's protected APIs for user creation and profile editing. For an already populated database, grant admin access through `BETTER_AUTH_ADMIN_USER_IDS` or an existing admin account.

The `users` collection in `bebop.config.ts` demonstrates `access.admin`. Its callback receives the verified Better Auth `req.user` plus `req.isAdmin`; by default the handler uses `req.isAdmin`, which accounts for both admin roles and IDs configured in Better Auth. The playground's `/api/bebop/admin-access` route evaluates that callback and sends only the allow/deny result to the browser.

Tasks have an optional Image upload field. The Media collection accepts `image/*` files up to 20 MiB. In the admin, choose an existing image, create one from the Task form, or drag an image into the field. The same Media collection has a standalone editor for file replacement, preview, and download. Creating Media from a Task keeps it in the library even if the Task form is canceled.

The current Jazz dependency is pinned to `2.0.0-alpha.58`. Workspaces and Media explicitly define access: active members and global admins can read workspaces; active workspace admins can rename them; Media is publicly readable, and writes are limited to the creator and global admins. Workspace creation uses a server-side exclusive transaction to create the workspace and first membership together. Memberships use command writes, with direct browser writes blocked by Jazz policy. Better Auth administrator roles and configured `BETTER_AUTH_ADMIN_USER_IDS` are represented in a trusted Jazz JWT claim; global admins receive collection CRUD access while command collections still require server authorization. Better Auth user operations remain behind its Admin plugin. The playground and admin use the generated Bebop mutation client so collection hooks and validation run; direct Jazz mutations bypass those callbacks. Review command authorization and collection permissions before deploying.

Run `pnpm --filter @bebopdev/playground test:e2e` for the browser smoke flow. Release acceptance also requires the documented 10,000-document admin performance benchmark; see [`docs/v1.0.0-release-checklist.md`](../../docs/v1.0.0-release-checklist.md).
