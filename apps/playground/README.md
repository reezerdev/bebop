# Bebop playground

This app exercises `@bebopdev/core` and mounts the first-party `@bebopdev/admin` package. Bebop owns the Better Auth adapter, JWT plugin, Admin plugin, and Users list; the playground supplies the Vite host, Jazz provider, handler mount, secret, and public URL. Access to `/admin` is checked server-side with Better Auth's Admin plugin before the UI is mounted.

Add `BETTER_AUTH_URL=http://127.0.0.1:5173` and a private `BETTER_AUTH_SECRET` to `.env` (see `.env.example`; generate the secret with `openssl rand -base64 32`). Run `pnpm generate` from the workspace root to generate Better Auth's Jazz schema, Bebop's generated schema and client, admin manifest, and permission files. Better Auth's Admin plugin controls access to `/admin` and its user APIs; `BETTER_AUTH_ADMIN_USER_IDS` can grant admin rights to additional trusted user IDs.

Jazz tooling expects a root `schema.ts`, so Bebop keeps that file as a small re-export entry point for `bebop-generated-schema.ts`.

Start the workspace with `pnpm dev`, then open `http://127.0.0.1:5173/` for the simple tasks playground or `http://127.0.0.1:5173/admin` for Bebop's admin UI. The `bebop` CLI watches `bebop.config.ts` and its local imports and regenerates the schema, permissions, and admin manifest on changes. The Jazz Vite plugin starts the local Jazz development server and watches those generated files. If the Better Auth users collection is empty, the sign-in screen asks whether to create the first admin account. The server grants the admin role only while that collection has no users; the prompt is skipped when a seed or earlier registration already populated it. Later signups receive the ordinary user role.

Create a workspace first, then add tasks. The playground also creates an active admin membership for the signed-in user when it creates a workspace. The admin can edit Workspaces, Workspace Memberships, Tasks, and Media. Workspace Memberships use the Better Auth command route and wait for Jazz's global confirmation; Tasks use local-first direct writes. The `users` collection has `auth: true`; task and membership relationships use `relationTo: "users"` and map to Better Auth's protected Jazz user table. Each task's required `author` defaults to the signed-in user. Its authenticated `/api/bebop/users` endpoint returns only user IDs and names for user selectors; Better Auth tables remain unreadable to browser Jazz clients. Jazz separately records the actual creator in `$createdBy`.

The Users collection page is visible to Better Auth administrators and reads through the built-in Admin plugin. It currently provides a searchable, paginated user list; user creation and profile management remain available through Better Auth's server APIs. For an already populated database, grant admin access through `BETTER_AUTH_ADMIN_USER_IDS` or an existing admin account.

The `users` collection in `bebop.config.ts` demonstrates `access.admin`. Its callback receives the verified Better Auth `req.user` plus `req.isAdmin`; by default the handler uses `req.isAdmin`, which accounts for both admin roles and IDs configured in Better Auth. The playground's `/api/bebop/admin-access` route evaluates that callback and sends only the allow/deny result to the browser.

Tasks have an optional Image upload field. The Media collection accepts `image/*` files up to 20 MiB. In the admin, choose an existing image, create one from the Task form, or drag an image into the field. The same Media collection has a standalone editor for file replacement, preview, and download. Creating Media from a Task keeps it in the library even if the Task form is canceled.

The current Jazz dependency is pinned to `2.0.0-alpha.57`. Workspaces and Media grant each operation explicitly with `rule.always()`. Workspace Memberships use authenticated rules and command writes; the Better Auth session is exchanged for a JWT that Jazz verifies and attributes. Tasks use direct writes and check `workspaceMemberships` for active membership in the task's Workspace. Task author and assignee rules compare against the verified Better Auth subject claim. Better Auth tables use generated permissions. The playground and admin use the generated Bebop mutation client so collection hooks and validation run; direct Jazz mutations bypass those callbacks. Review all configured permission rules before deploying.

The development app ID is `bebop-first-admin-playground-20260929`, which gives the playground a fresh Jazz data namespace and browser database for first-admin setup. Historical migration files remain in the repository.
