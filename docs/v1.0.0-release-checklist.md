# v1.0.0 release checklist

This checklist tracks the release gates for the first stable Bebop release. Keep package version changes and publishing separate from validation; prepare the `1.0.0` version change only after every required gate is complete.

## Automated gates

- [x] Core check, unit tests, and build (local).
- [x] Admin check and unit tests, including editor conflict and pagination helpers (local).
- [x] Playground schema validation, TypeScript check, production build, and permission tests (local).
- [x] CLI unit tests (local).
- [x] Playwright browser smoke: first-admin setup, workspace creation and switching, task scoping and creation without a Workspace form field, admin Task create/edit with its Workspace field, remote edit conflict, list pagination, and search (local).
- [ ] Additional browser smoke for Media selection, delete, relation/join navigation, and permission-denied UI states.
- [x] Packed-package consumer check (`pnpm test:packages`, local).
- [ ] CI passes on the release commit.

## Security review

- [x] Verify workspace creation atomically creates the creator's active admin membership.
- [x] Verify active-member/global-admin workspace reads, workspace-admin rename, own-membership reads, and denial of forged membership commands (unit and Jazz permission tests).
- [x] Verify Media is publicly readable and writes are limited to its creator and global admins (Jazz permission test).
- [x] Verify full CRUD for role-based and `BETTER_AUTH_ADMIN_USER_IDS` admins, and verify command collections still deny direct browser writes (compiler and Jazz permission tests).
- [ ] Review the backfill plan for existing workspaces whose creator membership cannot be identified; preserve data and do not assign ownership speculatively.

## Admin performance gate

Run against a documented local environment with 10,000 task documents and 20 warmed runs for each interaction: initial list, two-field search, and page changes. Record hardware/OS, Node and pnpm versions, Jazz version, dataset generation method, and p50/p95. Pass only if each interaction has p95 at or below two seconds and browser instrumentation confirms that no full-result ID subscription is created.

| Interaction | Runs | p50 | p95 | Full-result ID subscription |
| --- | ---: | ---: | ---: | --- |
| List | 20 | not measured | not measured | verify |
| Two-field search | 20 | not measured | not measured | verify |
| Page change | 20 | not measured | not measured | verify |

**Status:** pending. Do not treat the performance gate as passed until measurements and the subscription check are recorded above.

## Stable release

- [ ] Resolve all outstanding gates and review the final release notes.
- [ ] Change the public package versions to `1.0.0` and regenerate the lockfile after gates pass.
- [ ] Run the complete CI and packed-package consumer check against the versioned release commit.
- [ ] Publish as a separate, explicitly approved release operation.
